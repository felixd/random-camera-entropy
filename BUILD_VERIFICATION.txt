======================================================

camera-entropy-distributed-v7.6.1(1).zip

Integration basis
-----------------
- The v7.7.0 source tree was produced from the user's complete v7.6.1 archive,
  not from a synthetic approximation or a partial patch target.
- The preparatory patcher's --check mode recognized all required v7.6.1
  integration anchors before any source modification.
- The resulting v7.7.0 tree was then reviewed and corrected directly.

Implemented in v7.7.0
---------------------
- General spatial masks: full, both checkerboard phases, grid and block.
- Configurable X/Y step, phase and block dimensions.
- Temporal XOR with a configurable spatial pixel offset.
- Strict non-wrapping edge handling; invalid offset borders are excluded from
  calibration, clipping checks, shadow masks, RAW validation and production.
- Deterministic row-major, serpentine and tile-interleave serialization.
- Cached mask-to-index traversal for production throughput.
- Independent smoke profiles plus a complete spatial comparison campaign.
- Spatial campaign JSON/HTML summary generation.
- New parameters persisted in runner configuration and worker reports.
- Persistent control-panel fields, profile presets and contextual hover/focus
  help for every spatial parameter.
- Authenticated read-only documentation browser under /docs/ for README,
  Markdown, text and project instruction/documentation files.
- Safe Markdown subset renderer: raw HTML is escaped and unsafe URI schemes
  are rejected.
- Sticky worker header now exposes phase progress from the same `/api/stats`
  fields as the detailed cards: warm-up remaining time, calibration pair count,
  and output progress after production starts.

Environment limitation
----------------------
The CAAS build image did not contain Flask/Werkzeug and could not install them
from its isolated package index. Therefore control_selftest.py was not run
against a live Flask test client here. The Flask-independent control integration
self-test and Jinja parser both passed. Flask is an explicit runtime dependency
in requirements.txt and the live control test should be run after installing
those dependencies on the target server.

Not executed here
-----------------
- physical USB/V4L2 or RTSP camera capture
- deployment through the target systemd/nginx configuration
- live browser interaction with the control panel
- full long-duration spatial qualification campaign

Recommended target-host acceptance
----------------------------------
1. Install requirements.txt in the production virtual environment.
2. Run control_selftest.py and all selftest_*.py files.
3. Start with smoke_spatial_baseline.sh and one grid/checkerboard profile.
4. Run smoke_spatial_profiles.sh only after the short smoke profiles pass.
5. Compare RAW pre-SHA3 heatmaps, multi-lag correlations and throughput before
   choosing a production mask. SHA3 output alone is not a selection criterion.
