Implemented scope
-----------------
- New fixed final-preproduction profile for dataset-y.
- Snapshot of every frame published at campaign start; every candidate consumes
  exactly the same complete snapshot and must finish with dataset-exhausted.
- Five fixed candidates run in parallel:
  * XOR 1 LSB, disjoint k=4, credit 0.5, SHA3-512 input 2048 (recommended);
  * XOR 1 LSB, disjoint k=4, credit 0.5, SHA3-512 input 1024;
  * XOR 1 LSB, disjoint k=2, credit 0.5, SHA3-512 input 1024;
  * XOR 2 LSB, disjoint k=4, credit 1.0, SHA3-512 input 1024;
  * Direct Y 1 LSB control.
- SHA-256 verification of every closed dataset chunk before campaign start.
- Whole-dataset streaming symbol statistics over every accepted production
  symbol, with aggregate and consecutive-window Hmin, bias and lag metrics.
- Bounded 64 MiB validation/output files remain independent of whole-dataset
  statistics, avoiding another unbounded extracted-data copy.
- Automatic release gates include full dataset exhaustion, completion of output
  targets, health tests, aggregate and worst-window source Hmin, SHA3 output
  Hmin/bias/lag and chi-square p-value.
- One standalone final_preproduction_report.html with embedded Plotly, exact
  parameters, tables, charts, complete JSON and automatic verdict.
- Read-only dataset-y jobs may run in parallel on independent worker ports;
  live camera sources remain exclusive.
- Full-width seven-stage Control Panel with sticky navigation and an external
  live-preview button; no embedded preview iframe.
- Profile presets set and highlight visible options. Incompatible or irrelevant
  controls are disabled in the browser and validated again in the API.
- Logical code split:
  profile_catalog.py, masking.py, entropy_extractors.py, stream_statistics.py,
  qualification_final_preproduction.py.
- Von Neumann extraction supports 0..4 consecutive passes with retention
  metrics for every pass. It remains disabled in the recommended candidate.
- LSB width remains limited to 1..4.
- ChaCha20 is deliberately not exposed as a hash-conditioner replacement;
  using it safely would require a separate DRBG key/reseed/lifecycle design.
