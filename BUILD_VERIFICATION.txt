Integrated buffered-source and control-server changes
- USB agent keeps V4L2 capture open and continuously drains frames while exposing source uptime/warm-up metadata.
- Recorder stores full Y8 or packed whole-frame LSB data in committed chunks with a configurable limit (300 GB by default).
- frame-buffer-latest is available during recording; frame-buffer-latest-complete points to the latest cleanly closed dataset.
- dataset-y can replay a stopped dataset or follow a growing dataset without consuming a partial frame.
- The default source path is relative: data/frame-buffer-latest.
- Control-server dataset preflight resolves relative paths from the project root, reads geometry from manifest.json and validates frames.csv.
- Job startup avoids the os.getpgid() race and returns structured JSON errors instead of generic HTML 500 responses.
- Entropy-credit input accepts localized decimal values and the web number field uses step="any".

LSB campaign corrections
- RCT/APT consume one 1..8-bit source symbol per selected pixel, before pixel-major-lsb-first bit serialization.
- RCT uses the SP 800-90B source-symbol repetition rule.
- APT uses the first/reference symbol of each window; binary mode also checks the complementary value.
- Default APT windows are 1024 source samples for binary profiles and 512 for non-binary profiles.
- Failed runs preserve and analyze non-empty partial BIN files, generate runner_summary.json and run_report.html, and do not create READY.json.
- Campaign reports prefer lifetime RAW/masked rates, expose the selected rate basis, show SHA3/credited-entropy ratio, and link failure JSON/profile logs.
- Batch LSB profiles disable VN, web images, live byte diagnostics, mask snapshots and binary geometry by default.
